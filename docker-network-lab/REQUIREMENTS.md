# Grading checklist

| Brief item | Where to find it |
|---|---|
| Phase 1 A/B: Private LAN and private DNS | README.md topology and IP/service table. Network membership, ping, both clients and DNS names in verified-evidence/verification.txt. |
| Phase 1 C/D: Backends, reverse proxy, load balancing | backend.py, compose.json, nginx.conf, and X-Backend response headers in the verification log. |
| Phase 1 E: HTTPS | init-runtime.sh, nginx.conf, trusted HTTPS output, and the TLS handshake in phase1.pcap. |
| Phase 1 F: Caching | Cache-Control, ETag, and verified HTTP 304 in the verification log. |
| Phase 1 G: Packet evidence | verified-evidence/phase1.pcap and the capture walkthrough in DEMO.md. |
| Phase 1 failure demonstrations | Sections F1–F5 in the full verification log. |
| Phase 2 A/B/D: DNS resilience, TTL and upstream recovery | Test-Phase2.ps1, measured results in PHASE2-REPORT.md, and the Phase 2 transcript. |
| Phase 2 C/E: Isolation and edge cutover | Two Docker bridges in compose.json, direct reachability checks, TTL behavior, and X-Edge results. |
| Phase 2 F: Faculty troubleshooting and viva | DEMO.md and VIVA.md. Complete these during evaluation. |

This submission uses the approved one-PC Docker topology. Docker bridge separation implements backend isolation. Both Nginx edges are connected to the backend network so the standby can take over. Runtime certificates and DNS records are generated by the launcher.
