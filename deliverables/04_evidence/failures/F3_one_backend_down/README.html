Layer and why

Application-layer load balancing with failover. When nginx's connect to the stopped backend is refused (TCP RST), proxy_next_upstream error timeout http_502 http_503 makes it retry the same client request on the other backend, so the client still gets 200. max_fails=1 fail_timeout=10s then takes the dead backend out of rotation for 10 s (shared by all workers via zone), which is why the probe right after a restore still shows only the survivor for a moment. The client never knew: it only ever talks to the edge. That is the point of a load balancer (like an AWS ALB target group with health checks).
