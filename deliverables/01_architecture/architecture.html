subspace_67 · Phase 1 architecture

Goal. A client opens https://app.subspace-67.test. Our own DNS server (mac_vachan) resolves the name to the edge (mac_aanya). nginx on the edge terminates TLS and load-balances each request round-robin to Backend A (mac_abhay) or Backend B (mac_vachan). The app is deliberately trivial: the network is the project.

Phase 1 gate. A client resolves app.subspace-67.test, connects over HTTPS with no certificate warning, and gets responses from both backends through the load balancer. It passed on all three Macs (see 04_evidence and the final gate check).

Roles are combined because we are a team of 3. The brief describes 4 machines. Mac 4 (the test client) is merged into Mac 1 (mac_vachan), and every Mac also acts as a client for its own checks. The brief allows combining roles, and the network behaviour is identical: each role is still a separate service on its own port, reached over the real Wi-Fi LAN.

Under every step: L3 IPv4 packets between 10.7.x.x addresses, L2 Wi-Fi (802.11) frames between MAC addresses (resolved with ARP), and L1 radio.

Where TLS ends. Client to edge is encrypted. Edge to backend is plain HTTP on the LAN, over a separate TCP connection that the edge opens. The backend logs therefore show the edge's IP as the TCP peer, and the original client appears only in X-Forwarded-For.

TCP/IP folds OSI 5-7 into one Application layer and 1-2 into one Link layer. The brief's mapping: DNS -> Application, HTTP -> Application, TLS -> Session/Transport, TCP/UDP -> Transport, IP -> Network, Ethernet -> Link. TLS sits between TCP and HTTP: it uses TCP's reliable byte stream and provides encryption, integrity and server authentication to the HTTP session above it.

5. Design decisions (and why)

  • .test with a hyphen. .test is reserved for testing (RFC 2606/6761), so it can't clash with a real domain. .local is avoided because macOS resolves it with multicast DNS (mDNS/Bonjour). Hyphen, not underscore: underscores are invalid in hostnames and break certificate validation.
  • Our own DNS server, used exclusively. Public resolvers would answer NXDOMAIN for our private zone. dnsmasq answers our names authoritatively (local=) and forwards everything else, so internet access keeps working. no-resolv prevents a forwarding loop once mac_vachan uses itself as its DNS server. TTL 60 s is short, so an IP change on demo day propagates quickly.
  • dnsmasq runs as a root Homebrew service. On macOS it always binds each listen address separately, and binding port 53 on a specific address needs root. It drops to nobody right after binding. The config is a byte-identical copy in /opt/homebrew/etc, because macOS privacy protection (TCC) stops a root launchd daemon from reading ~/Desktop. The first attempt crash-looped with dnsmasq exit code 3 ("filesystem problem").
  • TLS terminates at the edge. Only the edge holds a private key. Backends stay simple HTTP services on the private LAN, and one certificate covers both names (SAN: app + api).
  • Our own CA, trusted in every Mac's System keychain; never curl -k. The CA is name-constrained to subspace-67.test, so even if its key leaked it could not impersonate any other site. /usr/bin/curl on macOS honours the keychain trust settings, verified with ssl_verify_result=0.
  • Round robin with a shared zone. Without it, each of nginx's 10 worker processes keeps its own pointer, and one client can see A A B B. With zone team_backends 1m; the rotation and failure counters are shared.
  • Failover. max_fails=1 fail_timeout=10s plus proxy_next_upstream error timeout http_502 http_503 and proxy_connect_timeout 2s. If one backend refuses a connection, nginx retries the other one inside the same client request (F3: the client still gets 200), and it skips the failed one for 10 s. If both are down, nginx itself answers 502 Bad Gateway after a successful TLS handshake (F4).
  • No proxy cache, no gzip at the edge. Every request must reach a backend (so X-Backend alternates), and Cache-Control / ETag must pass through untouched for the caching demo (304s).
  • Identical backend code. Byte-identical backend.py on both Macs (SHA-256 verified) with a byte-identical /api/cache-demo body. Both compute the same ETag, so a conditional request gets 304 whichever backend answers.
  • Real failures, not fake error pages. control.json + supervisor.py really stop a backend process, so its port closes and nginx gets connection refused (TCP RST).
  • Single points of failure (honest limits of Phase 1): the one edge and the one DNS server. In the cloud these become managed, multi-AZ services (ALB, Route 53).
